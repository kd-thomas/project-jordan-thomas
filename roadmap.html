DEVELOPMENT ROADMAP

See JORDAN being built.

JORDAN is being developed in public. The roadmap below reflects the actual progression from project foundation to working software, field testing, risk intelligence, and eventually a connected work-zone safety network.

Follow the Build on GitHub

BUILDING IN PUBLIC

From foundation to connected work zones.

The goal is not to build every possible feature at once. Each phase should prove something important before JORDAN moves into the next stage.

PHASE 01 COMPLETE

Foundation

Establish what Project Jordan Thomas is, what JORDAN is intended to become, and the public foundation supporting its development.

  • Project Jordan Thomas identity
  • JORDAN product identity
  • Approved visual brand system
  • Public GitHub repository
  • Public project website
  • Jordan's story and project mission
  • Initial national and Ohio work-zone safety research
  • Press and advocacy archive
  • Initial JORDAN product concept
  • Initial worker-to-action workflow
  • Development philosophy
  • Public development roadmap
PHASE 02 CURRENT

JORDAN MVP

Turn the product concept into the first functional version of JORDAN and prove the core road-worker safety workflow.

  • MVP technical architecture
  • Worker hazard-reporting experience
  • Project and active-crew context
  • Authentication and user roles
  • Crew membership
  • GPS and timestamp capture
  • Immediate crew alerts
  • Foreman visibility
  • Project and crew management
  • Report history
  • Initial corrective-action workflow
  • Foundational application data model

The MVP does not need to solve every work-zone safety problem. It needs to be useful enough for one real crew to say: “Yes. This would help us.”

PHASE 03 PLANNED

Risk Intelligence

Turn individual field reports into measurable safety intelligence that can show where, when, and how risk keeps recurring.

  • Recurring-risk detection
  • Time-based patterns
  • Location-based patterns
  • Repeated dangerous-driver reports
  • Vehicle-intrusion trends
  • Near-miss clustering
  • Unresolved hazard tracking
  • Corrective-action history
  • Safety trend dashboards
  • Evidence generation
PHASE 04 PLANNED

Ohio Pilot

Put JORDAN in front of real Ohio road workers and use field feedback to determine whether the product is genuinely useful during an actual workday.

  • Deploy with first participating road crew
  • Worker usability testing
  • Foreman feedback
  • Field workflow observation
  • Measure reporting speed
  • Measure crew adoption
  • Analyze report quality
  • Test alert usefulness
  • Validate corrective-action workflows
  • Iterate based on real worker feedback
PHASE 05 FUTURE

Connected Work Zones

If JORDAN proves useful at the crew level, explore how safety information can move beyond a single worker, crew, or project when doing so can help prevent harm.

  • Public roadway data
  • Transportation-agency partnerships
  • Jurisdiction-aware routing
  • Work-zone data standards
  • Roadway incident feeds
  • Navigation-system research
  • Connected work-zone infrastructure
  • Expansion beyond Ohio

FOLLOW THE ACTUAL DEVELOPMENT

The roadmap does not stop at this page.
